本方案按现有项目的技术结构划分四人的系统建设责任，用于分配实现、联调、测试、维护和答辩任务。成员一至成员四可替换为姓名。本表不根据提交记录推断个人历史贡献，具体完成情况由小组验收后填写。

## 二、成员一 · 素材与参考图处理系统

### 建设目标

建立可追溯、可扩展的原料体系，把不同格式、方向、尺寸与背景的图片转成生成引擎和区域编辑系统可以稳定使用的输入。

### 负责的功能与具体工作

1. **素材组织与来源管理**。按日用品、人物与宠物、川大建筑、网络热梗组织素材，维护稳定的素材 ID、分类、原图、作者、来源链接、授权和处理记录。
2. **图像读取与规范化**。识别静态 PNG、JPEG、WebP，进行 EXIF 方向校正、透明背景合成与 RGB 转换。维护统一的高像素缩放规则，供上传和本地素材读取复用。
3. **CPU 主体分割**。集成 U2Netp ONNX，完成输入张量预处理、前景概率图还原、阈值与异常蒙版检查，并处理分割模型未安装时的状态。
4. **A/B 差异化处理**。依据结构图与外观图的角色执行不同策略。需要保留场景或使用区域坐标时，A 保持规范化画布；B 可提取前景、裁剪留边并合成白底。
5. **候选视觉分析**。提取主体轮廓、前景完整性和 HSV 配色特征，提供可解释的分项评分。对角色身份、重复脸部和审美质量的判断边界作明确说明。
6. **普通背景合成**。维护整图生成时的可选背景保留逻辑，输出实际合成蒙版。区域模式的最终恢复由成员三负责。
7. **素材扩展入口**。使新增热梗、校园地标和宠物示例能够通过来源清单与预设配置接入，不需要复制新的图像处理流程。

| 规范化 A、分割状态 | 对应尺寸的前景蒙版和坐标说明 | 成员三 |

### 搭建顺序

先建立素材清单与图像规范化，再跑通 CPU 分割，随后加入 A/B 处理策略，最后完成候选特征与普通背景合成。

### 交付物与验收

- 一套能在工作台加载的原料与来源清单。
- 原图、处理图、前景蒙版对照，以及分割模型下载与检查工具。
- 高像素、EXIF、透明背景等检查用例。
- 评分分项、计算说明与至少一个反例。
- 透明杯、毛发边缘或复杂背景的失败案例说明。

验收时检查方向与颜色模式正确、高像素图等比缩放、图与蒙版尺寸一致、背景处理策略可追溯。分割异常应明确报错或按既定规则降级。参考分不能标注为审美或身份还原评分。

### 独立演示与答辩重点

展示一只白杯和一张宠物图的原图、处理图与蒙版，解释预处理、分割阈值、A/B 策略，以及为什么配色接近不等于融合成功。

## 三、成员二 · 双参考生成引擎与运行服务

### 建设目标

建立从用户配置到真实生成结果的执行链路，统一模型、工作流、任务队列和运行记录，使结果可以查看参数并再次运行。

### 负责的功能与具体工作

1. **模型环境搭建**。固定 ComfyUI 版本，配置生成模型、文本编码器与 VAE，维护配套 CUDA PyTorch / torchvision，校验模型大小与哈希。
2. **双参考提示编译**。将用途、A/B 角色、用户说明、背景与区域约束编译成实际送入模型的提示词，保留基础对照与结构化配方。
3. **风格与常用指令目录**。维护稳定的风格 ID、中文名、分组、视觉描述和指令模板，使界面可以独立选择用途与风格。
4. **原生工作流构造**。构建 ComfyUI API/UI 工作流，绑定双图条件、种子、像素预算、采样器和输出节点，并接入成员三的区域采样图。
5. **推理通信**。实现参考图与蒙版上传、任务提交、状态查询、生成文件下载和错误传播。
6. **任务调度**。维护单消费者队列、串行候选、任务取消的安全边界、重启恢复、失败状态和已完成结果保留。
7. **处理模块编排**。调用成员一的参考处理和候选分析、成员三的区域准备与恢复模块。调度层保存处理结果，不重复实现相同算法。
8. **实验持久化**。记录原始配置、实际提示词、模型版本、工作流、参考图、种子、预算、耗时、中间图和所有候选。
9. **部署与自检**。维护安装入口、依赖约束、模型下载、环境检查、服务启动和使用日志。

## 四、成员三 · 区域交互与精细编辑系统

### 建设目标

打通用户画选区、生成采样约束、局部高清与原图像素恢复，使功能结构和细节的修改范围可控、可检查。

### 负责的功能与具体工作

1. **区域编辑交互**。实现修改区、保护区的绘制、调整、删除、确认与取消，区分草稿和已确认参数。
2. **坐标映射**。统一画布显示坐标、归一化矩形、规范化原图像素与 latent 网格的映射，处理缩放和不同宽高比。
3. **蒙版集合运算**。计算修改区并集、扣除保护区，在可用时与前景相交，仅向内羽化，输出硬蒙版与软蒙版。
4. **保守 latent 映射**。避免细保护条缩小后消失，对缺少有效采样格的区域给出明确拒绝信息。
5. **区域生成图接入**。使用 A 的编码 latent 和实际噪声蒙版，供成员二装配到统一工作流。
6. **局部高清**。提取带必要上下文的采样窗口，重新构造局部参考与蒙版，记录裁剪框、尺寸与映射关系。
7. **结果恢复**。校验推理尺寸、映回源坐标并恢复禁改像素，分别保存原始生成、最终结果及实际编辑蒙版。
8. **连续重炼**。与成员四联调已生成图作为新 A 的流程，维护新图、参考图和选区之间的关系。
9. **区域实验与指标**。维护同输入、同种子的整图/区域对照，分别测量原始输出误差与最终保护像素变化。

### 搭建顺序

先验证画布坐标，再完成蒙版运算，随后接入 latent 采样与像素恢复，最后增加局部窗口、连续重炼和成对实验。

### 交付物与验收

- 可独立挂载的画布和区域编辑组件。
- 区域准备、采样图、局部高清与恢复模块。
- 非方形图、细保护条、边缘选区及高像素源图的检查。
- 三类物体、两个种子的成对实验与完整结果。
- 一个局部重炼前后示例及其保护像素指标。

验收时确认框选与实际位置一致、确认和取消语义正确、保护区扣除有效、回贴范围没有越界。最终蒙版为零处的像素必须与规范化 A 一致。原始输出和最终恢复分开评价，局部指标标明窗口范围。

## 五、成员四 · 创作工作台与应用接口系统

### 建设目标

把前三个系统组织成完整创作工具，负责用户入口、HTTP 契约、交互状态、结果展示和历史回看。

### 负责的功能与具体工作

1. **API 应用层**。实现上传、预设、画风目录、任务提交与查询、取消、历史、导出及文件读取，统一请求校验和错误响应。
2. **上传接入与路径管理**。执行文件类型、字节数、路径和参数限制，接入成员一规定的规范化及高像素缩放规则。
3. **创作参数界面**。实现 A/B 原料卡、替换与交换、示例分类、用途、画风预览、快捷指令与高级设置。
4. **文字与配置状态**。追加指令时保留手写内容、避免重复；预设、历史与重炼恢复对应参数，兼容旧记录。
5. **画布组件接入**。接入成员三的区域编辑器和结果画布，维护已确认区域，处理更换 A 和取消编辑的状态。
6. **生成过程交互**。展示真实任务状态、候选、错误和取消结果，处理断线、超时及重复提交。
7. **结果与历史**。实现候选选择、原始/合成切换、前后对比、蒙版查看、下载和实验 JSON 导出。
8. **可用性**。检查桌面、窄屏和演示模式布局，键盘操作、焦点与加载状态。
9. **浏览器集成验收**。验证上传到生成、下载、历史恢复和连续重炼的操作链路。
10. **使用说明**。维护使用步骤与演示操作顺序，各系统技术内容由对应负责人供稿。

| 任务与结果 | 成员二 | 成员四 | 状态、错误、候选、取消与恢复一致 |
| 指标 | 成员一、三 | 成员二保存、成员四展示 | 标明计算方式、版本和评价范围 |

每个物理文件指定一个主维护人。app.py 的 HTTP 层由成员四维护，图像处理规则由成员一提供；engine.py 由成员二维护，区域逻辑通过成员三的函数接入。公共函数变更需要通知调用方，不在不同系统复制相似处理逻辑。

## 七、联合交付与阶段验收

| 阶段 | 四人共同目标 | 主验收内容 |
| --- | --- | --- |
| 阶段一 · 接口冻结 | 确定 A/B 角色、参数、坐标与结果字段 | 同一配置能够被四个系统一致解释 |
| 阶段二 · 最小链路 | 原料处理 → 真实生成 → 区域恢复 → 页面查看 | 一次完整结果可下载、参数可追溯 |
| 阶段三 · 异常与兼容 | 大图、透明底、旧记录、窄选区、断线和取消 | 错误可解释，状态与结果一致 |
| 阶段四 · 成对实验 | 固定素材、种子、预算，记录成功和失败 | 区分模型原始误差、后处理保证与人工评价 |
| 阶段五 · 目标电脑复现 | 在展示电脑和同学电脑安装运行 | 每台受测设备完成实际出图，记录配置与限制 |
| 阶段六 · 展示交付 | 报告、PPT、视频与现场操作 | 每人能够解释本系统的实现、证据与局限 |

报告、PPT 和视频由四人分别提供本系统的结构、关键代码、接口、成功例子、失败例子与测量结果。统一编辑与演练属于联合交付，不把技术总结默认集中到某一名成员。

### 每人可单独提交的材料

- 一页本系统的目标、结构与接口说明。
- 一份由自己维护的模块文件表和调用关系。
- 一组功能验证记录，包含成功结果与至少一个边界情况。
- 一个可以独立操作的演示流程。
- 一段对本系统局限及下一步工作的说明。

### 后续功能的归属

提示词增强若继续开发，由成员二负责模型与 GPU 调度，成员四负责流式展示、取消与回退。必须先完成与生图互斥、模型执行与界面联调验证，再列入已验收能力。待审 PR 中的功能不自动视为主项目已交付功能。
