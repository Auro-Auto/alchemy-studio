## 二、罗旭威 · 素材库与输入规范化系统

### 建设目标

维护可直接使用、来源可追溯的素材与示例，将不同格式、拍摄方向、透明通道和像素数量的图片转成后续系统可以统一处理的输入。

### 负责的功能

1. **素材分类与文件组织**。整理日用品、宠物、校园地标和热梗原料，为每张图设置稳定文件标识和用途说明。
2. **来源与处理记录**。维护作者、原始链接、授权、裁切缩放记录和校验信息，使素材可以追溯。
3. **示例配置**。维护热梗等示例中 A/B 图的绑定关系、标题、用途、默认文字、画风和种子；示例字段约束由肖轩的应用接口校验。
4. **方向与颜色规范化**。依据 EXIF 旋转或翻转图像，将输入统一到 RGB；透明背景合成到白色。
5. **高像素等比缩放**。复用统一函数，将可接受的高像素图降到 20MP 内，保留宽高比，记录是否缩放和缩放前尺寸。
6. **上传元数据**。与肖轩约定上传返回的 id、url、width、height、compressed，以及本地元数据中的 compressed_from、源文件哈希等字段。
7. **输入检查与回归案例**。准备横图、竖图、EXIF 旋转、透明图、高像素图及非法输入，验证普通上传和直接素材引用采用相容的规范。

### 代码与文件范围

| 文件或区域 | 罗旭威负责的内容 | 协作边界 |
| --- | --- | --- |
| [input/](../input/) | 原料、来源清单、分类、示例配置与引用关系 | 顾祥瀚提供用途和画风 ID，肖轩负责页面加载 |
| [studio/vision.py](../studio/vision.py) | fit_within_max_pixels、_open_image、_rgb 的输入规范与验证 | 分割、前景特征与后处理由鲜超旭负责，公共函数变更共同复核 |
| [studio/app.py](../studio/app.py) | inspect_image、store_upload 的图像处理规则及元数据约定 | HTTP 路由、上传字节限制、路径管理由肖轩维护 |
| [tests/test_vision.py](../tests/test_vision.py) | 高像素、方向和颜色等输入检查 | 分割和评分检查由鲜超旭维护 |

这部分以素材和输入为边界。前景分割网络、latent 蒙版、GPU 调度和模型采样分别由其他负责人讲解。

### 输入、输出与接口

输入为图片文件或上传字节、原始文件名、素材分类和来源信息。输出为方向正确的规范化 RGB 图、稳定的素材标识和规范化尺寸，以及必要的来源、哈希和缩放记录。

高像素图的处理目标为宽高乘积不超过 20,000,000。若原图像素数为 P = W × H，P 大于上限时取缩放系数 s = sqrt(20,000,000 / P)，新宽高按相同系数缩小并向下取整。既有缩放函数还会检查取整后的像素数量。

后续区域坐标和保护像素都以规范化后的 A 为基准。发生缩图后，不能把最终像素恢复的保证解释成对缩图前原始文件逐像素不变。

### 搭建步骤

先建立素材清单与 A/B 示例绑定，再验证 EXIF、RGB 和透明底处理，随后加入等比缩放与元数据，最后将上传和直接素材读取交给生成、区域系统联调。

### 交付物与验收

- 一组能在页面选用的普通、川大与热梗素材及来源记录。
- 输入规范说明和可复用的规范化函数。
- 至少一组方向、透明底和高像素处理前后对照。
- 上传返回字段与本地记录的示例。
- 非法文件和极端图片被拒绝的检查结果。

验收时核对显示方向、RGB 模式、等比缩放后的尺寸和元数据是否一致。上传字节上限与 Pillow 解压保护继续有效；自动缩放不表示任意大图都应被接受。

### 独立演示

准备一张透明图、一张带方向信息的手机照片和一张可接受的高像素图，展示规范化前后尺寸、背景和方向，再加载一个新增的川大或热梗示例。演示内容集中在输入处理和素材配置。

## 三、顾祥瀚 · 双参考生成与提示控制系统

### 建设目标

建立从用户配置到真实生成结果的执行链路，使模型、用途、画风、提示词与随机种子共同形成可追溯的任务。

### 负责的功能

1. 配置固定版本 ComfyUI、FLUX.2 Klein 生成模型、文本编码器和 VAE，维护配套的 CUDA PyTorch / torchvision。
2. 将 A/B 角色、用途、风格、用户原文和编辑约束编译成实际模型提示，维护基础对照与结构化配方。
3. 维护 22 种画风和 19 条常用指令的稳定 ID、分组、显示名及视觉描述。
4. 构造双参考 API/UI 工作流，绑定图像条件、种子、预算、采样器和输出节点，接入鲜超旭提供的区域工作流资料。
5. 实现参考图和蒙版上传、任务提交、状态查询、结果下载及错误传播。
6. 维护单消费者队列、候选串行执行、取消边界、重启恢复、失败状态和持久化记录。
7. 负责提示词增强的模型会话模板、生成参数、子进程生命周期和资源释放，使增强与图像生成共享调度约束。
8. 维护模型大小与哈希清单、安装器、环境检查、服务启动和运行日志。

提示词增强是否列为已交付能力，以主分支合并和实际验收结果为准。

### 主要代码与文件

- [studio/prompts.py](../studio/prompts.py)、[studio/creative.py](../studio/creative.py)、[studio/engine.py](../studio/engine.py)
- 提示增强模块及其专用检查，按最终合并的代码组织维护
- [scripts/build_workflow.py](../scripts/build_workflow.py)、[scripts/run_comfy.py](../scripts/run_comfy.py)

### 接口与搭建步骤

从肖轩接收通过校验的 image_a、image_b、recipe、style、prompt、mode、seed、megapixels、candidates 和区域参数。调用罗旭威定义的输入规范化入口、鲜超旭的分割和区域处理模块，返回任务 ID、状态、阶段、候选、错误和实际执行记录。

先验证原生双图工作流，再加入用途和画风控制，随后实现通信、队列与记录，最后完成取消、恢复、增强资源互斥和部署工具。

### 交付物与验收

交付可执行的双参考服务、用途与风格目录、API/UI 工作流、安装工具和固定输入种子的对照。验收时核对实际提示与记录一致、A/B 顺序正确、候选串行执行、失败保留已有结果、取消不会全局中断其他任务、重启不重复提交旧的运行任务。

提示增强必须同时验证模型实际输出、取消与异常回收，以及增强和生图不会并行占用同一 GPU。缺少对应显卡实测时，应保留兼容性限制。

### 独立演示

固定两张图和随机种子，切换用途或画风，展示实际提示、工作流及候选记录。增强功能验收后，再展示一条原提示如何变成结构化提示以及其实际生图结果。

## 四、鲜超旭 · 前景分割与区域精细编辑系统

### 建设目标

从规范化图片中得到主体和可编辑范围，打通用户选区、采样约束、局部高清与原图像素恢复。

### 负责的功能

1. 集成 U2Netp CPU ONNX 推理，完成张量预处理、概率图还原、异常蒙版检测与分割不可用时的状态。
2. 维护 A/B 的主体处理策略，保留 A 的坐标画布，对 B 进行可选前景提取、裁剪和留边。
3. 实现修改区与保护区的绘制、调整、删除、确认和取消，统一显示坐标、归一化坐标、源像素与 latent 网格。
4. 计算修改区并集、扣除保护区、可选前景相交和向内羽化，保存硬蒙版与软蒙版。
5. 实现保守 latent 映射和区域采样图，处理细保护条与缺少有效采样格的情况。
6. 提取带上下文的局部高清窗口，重建采样蒙版，校验尺寸并映回源坐标。
7. 实现普通背景合成及区域模式像素恢复，保存原始生成、最终结果、实际蒙版和保护像素指标。
8. 维护轮廓、配色、主体完整性等启发式评分，标明其适用范围。
9. 维护同输入、同种子的区域对照实验，区分模型原始输出误差与最终恢复保证。

### 主要代码与文件

- [studio/vision.py](../studio/vision.py) 中的模型会话、分割、prepare_reference、前景特征、候选分析和合成部分
- [scripts/prepare_segmentation.py](../scripts/prepare_segmentation.py)
- [studio/regions.py](../studio/regions.py)、[studio/local_detail.py](../studio/local_detail.py)
- [web/src/RegionEditor.jsx](../web/src/RegionEditor.jsx)、[web/src/Canvas.jsx](../web/src/Canvas.jsx)、web/src/regions.js
- [scripts/evaluate_regions.py](../scripts/evaluate_regions.py)
- 分割、区域、局部高清相关测试及 output/region_evaluation/、output/scu_detail/ 的实验资料

### 接口与搭建步骤

接收规范化 A/B、主体提纯开关和已确认的 edit_regions、protect_regions、edit_mode、region_detail。区域矩形采用归一化的 [x0, y0, x1, y1]，基于方向校正、尺寸规范化后的 A。

prepare_reference(...) 提供处理图与同尺寸蒙版；prepare_regions(...) 和 prepare_detail(...) 输出实际采样资料；finish_region(...) 和 finish_detail(...) 返回最终图、实际编辑蒙版和恢复指标。顾祥瀚负责调度保存，肖轩负责页面入口、状态和视图切换。

先验证分割与源坐标，再完成画布和集合运算，随后接入 latent 约束和像素恢复，最后增加局部窗口、连续重炼及成对实验。

### 交付物与验收

交付分割与区域模块、可独立挂载的画布、局部高清及恢复逻辑、检查用例和成对实验。验收覆盖非方形图、细保护条、边缘区域、直接引用高像素 A、取消选区和更换 A。

保护区应从修改区扣除，最终蒙版为零的像素与规范化 A 相同；原始生成与最终合成分别记录。局部误差只解释相应窗口，参考分不代表身份或审美质量。回贴前应检查尺寸和裁剪范围。

### 独立演示

先展示一个主体分割和一个漏分例子，再比较同输入种子的整图与区域生成。最后选中望江浮雕杯的牌匾重炼，解释采样窗口、蒙版与保护像素。

## 五、肖轩 · 创作工作台与应用接口系统

将素材、生成与区域处理组织成完整创作工具，负责用户入口、HTTP 契约、交互状态、结果呈现和历史恢复。

### 负责的功能

1. 维护 FastAPI 应用，接入上传、预设、画风、任务提交查询、取消、历史、导出与文件读取。
2. 执行文件字节数、类型、路径与参数校验，接入罗旭威制定的图像规范和上传元数据。
3. 实现 A/B 原料卡、替换交换、分类示例、用途、画风预览、常用指令与高级设置。
4. 保留用户手写文字，处理指令去重、用途加载、历史回填和旧记录兼容。
5. 接入鲜超旭的画布与区域组件，管理已确认参数、编辑草稿、更换 A 和连续重炼。
6. 展示实际任务进度、候选、错误和取消状态，处理断线、超时与重复提交。
7. 实现原始/合成视图切换、前后比较、蒙版查看、下载和实验 JSON 导出。
8. 接入提示增强的流式状态、取消、错误恢复与回退；GPU 资源调度由顾祥瀚提供。
9. 维护桌面、窄屏、键盘与演示模式，完成浏览器层集成验收。

### 接口与搭建步骤

向顾祥瀚传递校验后的生成配置，按任务 ID 查询状态；向鲜超旭的组件传递当前图片和已确认区域，接收确认后的参数。上传返回值必须与罗旭威规范化后的图片一致，历史和下载必须对应当前选择的实际结果。

先冻结 API 与任务状态约定，再搭建上传、参数和任务页面，接入候选、区域、重炼与增强，最后验证历史、下载、异常恢复和响应式布局。

### 交付物与验收

交付完整工作台、API 契约、状态与错误信息规则，以及桌面和窄屏的浏览器检查。正常链路应能完成上传、生成、比较、下载和回看；非法输入明确拒绝，失败不标成成功，示例预览与实际生成可区分，确认/取消行为一致。

增强功能需验证流中断或取消能恢复原提示，回退记录不会跨到另一份任务。界面通过模拟流仅表示交互通过，真实模型输出和 GPU 调度还需由顾祥瀚联合验证。

### 独立演示

## 八、罗旭威的演示与答辩准备

建议主讲“素材怎样进入系统”，按“选择素材 → 输入检查 → 规范化 → 处理记录”演示。这个范围可以直接用处理前后的图片与尺寸说明，先熟悉所负责的函数和测试。老师仍可能询问系统接口及整体流程，需要知道下一步交给谁处理。

| 可能的问题 | 可据实现回答的要点 |
| --- | --- |
| 1. 你的系统负责什么？ | 整理素材和来源，并把不同方向、颜色模式和尺寸的图片转为统一输入，供生成和区域处理使用。 |
| 2. A、B 两张图分别有什么用？ | 通常 A 提供结构或场景，B 提供外观、材质或表情；具体换装、梗图等任务由用途和用户指令明确角色。 |
| 3. 为什么要处理 EXIF？ | 手机照片可能把拍摄方向写在元数据里，像素本身未旋转。先按 EXIF 校正，后续显示和选区坐标才能使用同一个方向。 |
| 4. 为什么统一为 RGB？ | 统一后续输入的通道表示，避免灰度、调色板和透明图走不同处理路径。透明通道在转 RGB 前先合成白底。 |
| 5. 透明背景怎样变成白底？ | 用透明度作为权重，将原颜色与白色合成。透明度为 1 时保留原色，为 0 时得到白色。 |
| 6. 大图怎样缩小，为什么不会拉伸？ | 总像素超过上限时，宽和高都乘 s = sqrt(20,000,000 / (W × H))，再取整，因此两条边使用同一缩放比例。 |
| 7. 20MB 和 20MP 有什么区别？ | MB 是文件字节量，受编码和压缩影响；MP 是宽乘高的像素数量。一个限制上传文件大小，另一个控制处理画布和内存。 |
| 8. 为什么要记录 compressed_from？ | 用它说明输入曾经缩放及缩放前尺寸；返回的 width、height 则对应实际保存、供后续处理的图。 |
| 9. 保护区像素不变，是对哪张图说的？ | 对方向校正、颜色转换和尺寸规范化后的 A。若之前缩过图，不应说与缩图前原文件的每个像素都相同。具体恢复由鲜超旭的系统完成。 |
| 10. 怎么证明输入处理是对的？ | 对照原图与输出，检查方向、RGB 模式、宽高比、像素上限和元数据，再用测试覆盖透明图、方向图、高像素图及非法输入。 |
| 11. 为什么缩图使用 Lanczos？ | 代码选用现成的 Lanczos 重采样，在等比缩小时保留细节。它是传统图像插值，不是调用生成模型补画，仍可能改变原像素。 |
| 12. 你们训练了什么新模型？ | 本项目使用已有 FLUX.2 和 U2Netp 预训练模型。我们的工作是参考图处理、双图工作流、区域采样约束、局部处理、结果恢复与应用集成；我负责其中的素材和输入规范化。 |

素材授权、分割、模型生成各有独立职责。介绍整体项目时，可以说明规范化输出交给顾祥瀚的生成服务，主体和区域处理由鲜超旭负责，用户操作与 API 由肖轩负责。涉及尚未实测的设备和效果，应引用实际验证记录。
